# doc-protocol — 文档职责路由与进度真值协议

写任何项目文档前先读本文件。核心治法一句话：

**每类事实只有一个权威载体；其它地方放指针，绝不复制内容或数字。**

判断标准极简：发现自己**在第二处抄同一事实（尤其数字）**时 —— 停下，删副本改指针。

**本技能分两层**：

- **第一~八节 = 通用原则** —— 可移植到任何仓库，不预设任何具体文件名。
- **第九节 = 落地** —— 通用原则怎么映射到具体仓库，附 **stock-agent 的完整实例**
  （载体映射 / 特有裁定 / 实证索引），以及为别的仓库写落地档的骨架。

## 一、文档面分类学

下表给的是**类别**。落地时映射到该仓库真实存在的文件；**某类不存在就跳过，不要为它新建文件**。

「层」列见下方定义；**热层是唯一需要预算的层**。

| 类别 | 层 | 典型载体 | 唯一职责 | 不放 |
|---|---|---|---|---|
| **指令文件** | **热** | AGENTS.md / CLAUDE.md（自动注入上下文） | 跨会话硬约束：动手前必须遵守的规则与边界 | 事故叙事全链、易变数字、进度 |
| **交接/日志文档** | **热**(账本)·**温**(段区) | handoff.md / devlog | ①待办账本（唯一）②按段追加的会话日志 | 正文埋待办、结论固化后滞留不迁 |
| **里程碑史** | 温 | history.md / CHANGELOG | 战役级长期结论与硬边界 | 日志复制、数字快照、过程细节 |
| **入口** | 温 | README.md | 是什么 / 怎么跑 / 目录导航 | 任何会过期的数字 |
| **主题文档** | 温 | docs/ 子目录 | `operations/`=操作序列唯一权威；编号评审=时点证据 | 进度账本（处置状态只进账本） |
| **归档** | 冷 | docs/archive/ | 逐字搬入的老日志段（段头/段号原样保留，`第N段` 引用仍可检索） | 一切新内容、任何改写或「瘦身」 |
| **已退役文档** | 冷 | 任何带墓碑的文件 | 只保留墓碑，指向新真值源，不再更新 | 一切新内容 |
| **agent 记忆** | 温 | 各工具的记忆面 | 会话恢复导航：真值在哪的指针、跨会话偏好 | 进度数字、待办账本、结论副本、日期快照 |
| **git + 测试** | — | — | 过程与计数的唯一真值 | — |

**三层的定义与预算**（2026-10-05 补，对齐外部最佳实践）：

| 层 | 含义 | 访问策略 | 预算 |
|---|---|---|---|
| **热** | 每个会话都必读 | 精简 + 指针；**规则/决策整块保留、不碎片化** | 见第三节（指令文件）、第四节（活账本） |
| **温** | 按需读 | 追加不回改；**不整块读**，用 grep / offset 回填 | 按需（无固定预算，但要有归档线） |
| **冷** | 引用 | 追加型、不可变；单片有上限，超出即开新片 | 单片参考 **≤500 KB** |

**上下文税只由热层产生** —— 温/冷层的成本是「按需读一次」，热层的成本是「每会话读一次」，
所以**只有热层需要硬预算**。这是本协议体量治理的全部着力点。

**外部应用缓存目录**（其它工具生成的 `.xxx/` 缓存）**不是文档面**：不读、不维护、
不当进度或状态源；其中出现的结论副本与仓库文档冲突时，一律以仓库文档为准。

仓库**没有**交接文档时，待办账本落在该仓库唯一约定的位置（issue tracker 或既有任务文件），
**单一账本原则不变**；不为了记账新开文档，除非用户明确要。

## 二、事实路由表（写之前先查：这条信息属于哪一行）

| 事实类型 | 唯一去处 | 规则 |
|---|---|---|
| 本次会话做了什么、怎么验证的 | 日志新段 | 写「结果 + 证据 + 提交号」，不写「当前状态」（会过期） |
| 待办 / 遗留 / 挂起 / 未来验证点 | 待办账本 | 正文只留指针（「入表」），表外不记账 |
| 跨会话必须遵守的规则、边界 | 指令文件 | 过准入测试（见第三节）；迁入后原段不回改 |
| 事故完整叙事、根因链、复盘方法论 | docs/ 编号文档 | 时点证据，发布后不改写；后续处置进账本 |
| 里程碑、长期结论、「长期边界」 | 里程碑史 | 从日志段蒸馏；只留可复查结论 |
| 操作序列 / runbook / 检查清单 | docs/ 唯一文件 | 指令文件与日志只留一行指针（防双源漂移） |
| 任何计数（行数/接口数/测试数/规模） | 测试、spec、registry | **prose 里禁止落数字**；只允许「文件名 + 实测命令 + 日期」式引用 |
| 提交数、推送欠账、工作区状态 | git 实查 | 永不写进文档或记忆当「当前状态」；段内只记「本段产出 N 提交」这种不过期的事实 |
| 用户拍板（决策 + 理由） | 日志段 | 派生的待执行项进账本、规则进指令文件、里程碑进里程碑史 |
| 「去哪找真值」的导航、跨会话偏好 | agent 记忆 | 带日期；指向载体文件，不复制内容 |
| 新人理解项目所需 | README.md | 结构性描述；数字一律「以 X 实测为准」并给命令 |

## 三、指令文件准入测试

一条内容进入指令文件，当且仅当：**新会话不读它就会做出错误的事**。

- 通过 → 写成「**规则 + 一句归因（带日期）+ 指针**（日志段或 docs 文档）」。
- 不通过（只是历史 / 背景 / 一次性修复）→ 里程碑史或 docs，指令文件不收。
- **数字纪律**：可指名守卫测试文件，但**不复述数值** —— 数值以测试为真值，复述必过期。
- **反向义务**：日志里出现「结论固化 / 此后以此为准」字样时，收尾清单必须执行迁移；
  迁移靠清单兜底，不靠人记。
- 指令文件**每个会话都进上下文** —— 叙事越长，上下文税越高，真正「不读会做错事」的规则密度被稀释。
- **体量双预算**（2026-10-05 补）—— 指令文件是热层，光有定性准入测试挡不住膨胀，必须给数字：

  | 指标 | 预算 | 理由 |
  |---|---|---|
  | 字节 | **≤ 60 KB** | 多数工具读取指令文件的预算是 **100 KB**，超限**静默截断尾部**（不报警）。留 40% 余量对抗回弹 |
  | standing instruction 条数 | **≤ 150 条** | 经验值：约 150~200 条后模型遵从度下降。**超了先删陈旧项，再加新的** |

  **超限动作 = 抽叙事成独立文件**，指令文件里只留一行指针（渐进披露）。**不是删规则** ——
  规则/决策整块保留（见第一节分层），只把事故叙事、历史过程、运维细节移出去。
  字节与条数都进体量检查脚本（第七节第 0 步），**让回弹在越线前可见**。

## 四、待办账本模式（唯一账本）

**表钉在交接文档顶部、所有日志段之上；新段的插入点＝表的紧后方。**

> 严禁把新段插到表的前面。此处的经典事故：表在文件顶部创建，之后 50+ 个新段
> 不断从文件顶前插，把表推到第 1819 行 —— 新会话从顶部读**永远到不了那里**，
> 待办实质丢失，现状只能靠 grep「遗留」拼出。这不是维护缺失，是结构性缺陷。

**账本 = 一条追加型事件日志（冷层）的「未完成投影」（热层）。** 活表**只放未完成项** ——
这是可机械校验的不变量：**活表里不允许出现 `~~` 行**（判据 `grep -c '~~' 活表 == 0`）。

状态词表**只用三个**（都是未完成）：

- **🔴 待办** — 有人 / 有会话就能做。
- **🟡 挂起** — 等外部条件，**必须写重开触发线**（拍板 / 数据窗口 / 判据达成）；
  **无触发线的挂起是伪待办**。
- **⏳ 验证点** — 带未来日期与预期结果；过了日期未验证的，收尾时**升级回 🔴**。

**完成 = 移出，不是留痕**（2026-10-05 修订）。一个待办完成时，**在同一个收尾动作里做两件事**：

1. 该行追加到冷层 `docs/archive/<name>-ledger-<YYYY-MM>.md`（append-only，一行一条，注提交号）；
2. 从活表**删除**该行。

活表里**不放**「已结账」区、不放「最近 N 行已完成」。活表 ≠ 台账，它是台账的一个**视图**（过滤）。

> 为什么不留 `~~` 死行：**可复查性已由 git + 冷层共同兜底**（`git show <sha>` 即可复查），
> 表里留死行**不增加任何可复查性**，是纯负债 —— 而且完成率越高、死行越多。
> 实证：某仓库 42 行账本里 **25 行（60%）是死行**，占全文 14.1%；按每天 +1.5 条外推，
> 一年账本 +1.2 MB，**比整个交接文档还大**。

**体量预算**（2026-10-05 补）—— 账本是热层，必须有上限：

| 指标 | 预算 | 说明 |
|---|---|---|
| 活账本字节 | **≤ 15 KB** | 超限先按上面的「投影」把已完成项移出 |
| 活账本行数 | **≤ 40 行** | 含表头 |
| 活跃条数 | **≤ 30 条**（软） | 条数即价值密度；过多本身就是「该收敛」的信号 |

**单行软上限**：账本单行 **≤ 600 B**、「下一步 / 备注」列 **≤ 200 字**。
超长内容移入 `docs/`，表内留**指针**（留指针不留内容）。

行格式：

```markdown
| 状态 | 事项 | 来源段 | 下一步 / 触发线 / 验证日期 | 备注 |
|---|---|---|---|---|
| 🔴 待办 | market_read 阶段二抽取 | 第 55 段 | 先做 1-call 简单件 | — |
| 🟡 挂起 | A-3 选型 | 第 55 段 | 触发线=依赖选型拍板 | — |
| ⏳ 验证点 | grade 新语义首验 | 补记3 | 09-14 08:50 应脱离恒压 | — |
```

**卫生纪律（违反 = 下次会话拿到假进度）**：

1. 完成行**当轮移出** —— 投影到冷层 + 从活表删除，不留死行、不留「应该好了」的行。
2. 矛盾行**当轮**修正 —— 表内与实况不符立即改，不留给下一位。
3. 段落正文出现新待办时，**收尾前必须入表**；只在正文里写过的待办视为**丢失**。

## 五、日志段落规则

- **新段插入点 = 待办账本紧后方**（表钉顶）；其余段从新到旧向下排。
- **段 = 一个战役单元（通常 ≤1 个工作日）**。续会话跨日必开新段；
  同日补记 **≤3 条**，超过即开新段。
  > 反例：某段累积 43 条补记横跨 4 天，现状要读千行才能拼出。
- 段头格式：`## YYYY-MM-DD(第N段)标题 — 一句话结果`（**结果先行**，方便扫读）。
- 旧段是日志**不回改**；发现旧段错误 → **新段更正**（「口径更正」），或迁移后在账本修正。
- 每段收尾自查：「这段有没有 ①该迁指令文件的规则 ②该进里程碑史的里程碑 ③该入账本的待办？」
- **归档条款**：当交接文档超过约定体量阈值（参考：**2000 行** **或** **500 KB**，先到者）
  或最老段早于约 **6 周前**时，收尾清单执行归档 —— 按日期线切（保留账本 + 近期段），其余段 **逐字**搬入
  `docs/archive/<name>-archive-v{N}.md`（v 号递增，文件头注明日期区间），段头/段号原样保留，
  顶部留一行归档指针。
  **红线**：归档 ≠ 改写（老段的错误照原样进归档，更正走新段）；**账本永不随段归档**
  （其体量改由第四节的「投影出口」保证）；**日志段不倒进里程碑史**（里程碑史只收蒸馏结论，
  收日志 = 换个文件继续肥）。
  **冷层分片**：归档文件单片 **≤500 KB**，超出即开新片（片名含日期区间），活表顶部留指针。
  > **归档是「搬家」不是「收敛」** —— 逐字搬运 ⇒ 总量单调增长，只是把上下文税推迟。
  > 真收敛必须靠三样：①第四节的账本投影出口；②下条的补记机械化；③第八节的「陈旧即删」当义务执行。
- **补记机械化**：段内同日补记 **≤3**（`补记{N}` 写入时自查，N>3 即开新段）；段头格式
  `## YYYY-MM-DD(第N段)…`。两条都由体量检查脚本校验（第七节第 0 步）。
  > 实测某仓库 **≥17 段越限、最多 10 条** ⇒ 只写在协议里、不进闸，必然复发。

## 六、会话开场协议（恢复上下文，三读一查）

1. **指令文件**（多数工具自动注入，硬约束）。
2. **待办账本** —— 全部待办 / 挂起 / 验证点，读这一处就够。
3. **最新一段日志** —— 上次会话的结尾与证据。
4. 数字类「当前状态」**一律现查真值**，不从记忆、旧段、README 恢复：

```bash
git status --short                                # 工作区
git log --oneline "@{u}.." 2>/dev/null | wc -l     # 推送欠账（无上游用 origin/<branch>..<branch>）
git log --oneline --since="1 day ago"              # 近期会话提交
```

计数问题（接口数 / 数据集数 / 行数）：跑对应守卫测试或直接数 spec，再开口。

## 七、会话收尾清单（按序执行）

0. **体量闸**：跑体量检查脚本（见本节末）。**退出码非零 = 红 → 先处理越线，再做其余**。
1. **实查**：跑上面的真值命令，拿到提交数 / 欠账 / 工作区状态 —— **禁止凭记忆报数**。
2. **日志新段**：做了什么 + 验证证据（测试数 / 实测）+ 提交清单。跨日或补记 >3 → 新段。
3. **账本对账**：本段完成项**投影**（追加冷层 + 从活表删除，注提交号）；新待办 / 挂起 / 验证点入表；过期验证点升级。
4. **体量检查**：行数 **或字节** **或**最老段触阈值 → 当轮执行第五节归档（逐字搬运 + 顶部留指针）；
   活账本越预算 → 按第四节「投影」清理。
5. **迁移判定**（逐条过第二节的理由由头）：
   - 出现「此后以此为准」的规则 → 指令文件（过准入测试）。
   - 达成里程碑 → 里程碑史蒸馏一行 / 一段。
   - 沉淀出操作序列 → docs/operations（新文件前先确认没有既有文件可扩展）。
6. **记忆**：只写指针 / 偏好，不抄进度与数字。
7. **陈旧即删**：本段发现任何**不再为真**的指令 / 账本行 → **立即删，不等阈值**
   （「陈旧指令比缺失更糟」——说了假话会让模型不信任或照做）。
8. **红灯自查**（见第八节）：本段有没有抄数字、埋待办、开平行账本？有 → 当轮改。

> **体量闸**：本技能自带参考实现 `assets/check-doc-budget.py`，**不复制进仓库**（见 9.1 第 3 条）。
> 以技能安装态路径调用，`--root` 指向仓库即可：
>
> ```bash
> python ~/.agents/skills/doc-protocol/assets/check-doc-budget.py --root .    # ~/.zcode/skills/ 亦可
> ```
>
> 输出结构化 JSON（各文档行数 / 字节、活账本大小与 `~~` 死行数、是否越线、补记是否超限、
> 指令文件字节与条数），**越线即退出码非零**；阈值可由 `--config <repo>/doc-budget.json`（放仓库根）覆盖
> （默认值即通用值，多数仓库无需配置文件）。⚠️ 给了 `--config` 就**必须指向已存在的文件**，否则 exit 2
> —— 不要把它当可选参数随手加。它同时是**会话开场注入**的数据源 ——
> 把「账本 N KB / 交接 N 行 / 已越线」推到模型面前，让回弹在越线前可见（见 `references/stock-agent.md`）。

## 八、红灯信号（任一出现 = 停下，改指针 / 入表 / 删副本）

1. **在第二处抄同一事实** —— 尤其是数字。改法：删副本，留「以 X 实测为准 + 命令」。
2. **待办写在段落正文不进表** —— 下个会话靠 grep 才能拼出欠账，必然漏。
3. **记忆里记进度数字**（推送欠账=N 这类）—— git 才是真值，数字进记忆那一刻就过期。
4. **评审 / 核查文档回写处置进展** —— 时点文档变成第二个进度账本。处置状态只进账本。
5. **结论说「固化」但没有迁移动作** —— 规则滞留日志，指令文件失去约束力。
6. **指令文件塞事故叙事或数字** —— 它每个会话都进上下文，叙事放 docs，数字放测试。
7. **为一次性的进度问题新开文档** —— 默认答案是「进账本」，不是「再写一份核查报告」。
8. **活账本里出现 `~~` 行** —— 违反第四节的「未完成投影」不变量。死行是纯负债（可复查性由 git 兜底），当轮投影出去。
9. **发现不再为真的内容还留着**（陈旧指令 / 过期结论 / 指向已删文件的行）—— 立即删，不等阈值。

## 九、落到具体仓库

### 9.1 三种承载方式

通用原则要落到具体文件，有三种形态。**任选其一，不要同时用两种**（会开平行真值源）：

| 方式 | 形态 | 何时用 |
|---|---|---|
| **A 仓库内普通文件** | `<repo>/.agents/doc-protocol.md`（或 `.zcode/` 版） | 协议要随仓库分发、且不依赖技能安装 |
| **B 本技能内实例** | 本文件 9.2 节 + `references/stock-agent.md` | 只有一两个仓库在用，或不想往仓库里加文件 |
| **C 项目级技能** | `<repo>/.zcode/skills/<新名>/SKILL.md` | 想让 ZCode 自动加载项目差异 |

三条硬约束（ZCode 源码实测，2026-10-04；第 3 条 2026-10-05 补）：

1. **不能同名。** 解析 skill 根时每根带 `priority`（extraRoots=10 → 用户级 20/30 → 项目级 40/50+），
   按 priority **升序**排序后取**首个**匹配 ⇒ **用户级同名技能会遮蔽项目级**。
   症状是「文件在、改了不起作用」，极难排查。
   ⇒ 方式 C 的目录名**必须换名**（如 `doc-protocol-<repo>`）；方式 A 是普通文件，天然无此问题。
2. **落盘前跑 `git check-ignore -v <路径>`。** 被 gitignore 的落地档**不会随仓库分发**，
   换台机器协议就失效。（实例：stock-agent 的 `.gitignore` 是 `.zcode/*`，所以它只能用 `.agents/`。）
   ⇒ **这条对「任何要放进目标仓库的路径」都成立**，不止落地档 —— 插件配置（如 `guardrails.json`）、
   账本、技能目录、生成的文档，一视同仁。判据只有一条：`git check-ignore -v <path>` **必须无输出**。
   （**已栽两次**：doc-protocol 覆盖档 → 迁 `.agents/`；`project-guardrails` 的配置落点 → 改双路径。
   两次都是「规则写着，动手时没跑」。）
3. **技能自带的可执行件（`assets/`）不复制进仓库。** 脚本随技能分发，**安装态即最新**；
   在仓库里再放一份 = 同一个脚本两个真源，技能一改仓库那份就陈旧 —— 与「单一真值」直接冲突
   （同源错误：插件两跳拷贝、9.1 第 1/2 条的落地档）。判据是**有没有独立于技能安装的消费方**：

   | 消费方 | 落点 | 调用方式 |
   |---|---|---|
   | 只有 agent 会话（模型按技能指引手动跑） | **留在技能 `assets/`** | 技能安装态路径 + `--root <仓库>` |
   | CI / pre-commit / 他人 clone 后必须能跑 | 才在仓库建**实例** | 文件头注明「派生自 `<技能>/assets/<脚本>`@<版本或日期>」，技能修订时同步 |

   ⇒ **仓库侧只放配置（阈值/文件名差异），不放脚本本体。** 示例：`doc-protocol` 的
   `assets/check-doc-budget.py` 已用 `--root` / `--config` 完全参数化 ⇒ 目标仓库**零文件即用**。

> 给别的仓库写落地档，照 9.2 的骨架：**只写差异**（本仓库具体是哪些文件、本仓库的裁定）；
> 载体名必须具体；裁定带日期与出处；实证留在本仓库；与通用层一致的条款不必重复。

### 9.3 协议自身的单一真值

- 本技能（或按 9.1 落地的项目落地档）是文档分工的**唯一规范源**。日志头部、记忆里的
  「多文档分工」摘要一律改为**一行指针**指向此处，不再各自维护全文。
- 修订协议 = 改本文件，并在 `references/evidence.md` 追加依据。
- 每条规则对应的事故实证 → `references/evidence.md`（通用模式）/ `references/stock-agent.md`（该项目实例）。
