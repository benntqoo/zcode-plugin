# 项目覆盖档模板

## 它是什么

`doc-protocol` 技能是**通用层**（只写可泛化原则，不预设文件名）。
某个仓库若需要把通用原则**落到具体载体名**、记录本仓库的裁定与事故实证，
就写一份覆盖档：

```
<repo>/.agents/doc-protocol.md      ← 推荐（.agents/ 一般随 git 入库）
<repo>/.zcode/doc-protocol.md       ← 备用（若该项目不忽略 .zcode/）
```

技能开场读一次；命中即**以覆盖档为准**，通用层只填补空白。

> ⚠️ 落盘前跑 `git check-ignore -v <路径>`。被 gitignore 的覆盖档**不会随仓库分发**，
> 换台机器协议就失效。伴随文件（实证等）与覆盖档放同一目录。

> ⚠️ 覆盖档是**普通 markdown 文件**，**不要**做成项目级同名 skill ——
> ZCode 用户级 skill 优先于项目级，同名时全局那份会遮蔽项目那份。
> 详见 `SKILL.md` 第零节。

## 写法要求

| 要求 | 说明 |
|---|---|
| 只写**差异** | 与通用层一致的条款不必重复；只写「本仓库具体是哪些文件」「本仓库的裁定」 |
| 载体名必须具体 | 通用层写「交接/日志文档」，覆盖档写「`handoff.md`」；通用层写「已退役文档」，覆盖档写「`REFACTOR_PROGRESS.md`（2026-xx-xx 退役）」 |
| 裁定带日期与出处 | 「用户 2026-09-11 拍板：……」，便于日后复查 |
| 实证留在本仓库 | 事故叙事带本仓库的数字与路径；**不要**回写进通用层的 `evidence.md` |
| 不复述易变数字 | 与通用层同一条数字纪律 —— 指名守卫测试 / spec，不抄数值 |

## 骨架

```markdown
# doc-protocol — <repo 名> 覆盖档

> 本文件是通用层 `doc-protocol` 技能的项目覆盖。通用原则见技能本体；
> 本文件只写本仓库的具体载体、裁定与实证。冲突时**以本文件为准**。

## 一、本仓库的文档面（载体名映射）

| 类别（通用层） | 本仓库的实际文件 | 备注 |
|---|---|---|
| 指令文件 | `AGENTS.md` | |
| 交接/日志 | `handoff.md` | 待办账本在顶部「剩余未完成与遗留事项」 |
| 里程碑史 | `history.md` | |
| 入口 | `README.md` | |
| 主题文档 | `docs/operations/`、`docs/architecture/NN-*.md` | 编号评审=时点证据 |
| 归档 | `docs/archive/handoff-archive-v{N}.md` | 段头原样保留 |
| 已退役 | `REFACTOR_PROGRESS.md` | 2026-xx-xx 退役，墓碑指向 …… |
| agent 记忆 | `~/.zcode/cli/memories/` | |

## 二、本仓库特有裁定（带日期与出处）

- **2026-xx-xx**：……

## 三、本仓库的事故实证（抽象版见技能 `references/evidence.md`）

- **E2 实况**：账本曾被活埋在第 1819 行，55 段之下（2026-09-11 诊断）。
- ……

## 四、本仓库的体量阈值

- 交接文档归档线：**2000 行** / 最老段 **6 周**前（沿用通用层默认，或有本仓库override）。
```

## 迁移已有的项目级协议技能

若某仓库原先把协议写成了**项目级 skill**（如 `.agents/skills/<name>/SKILL.md`）：

1. 把该 SKILL.md 正文（去掉 frontmatter）搬进覆盖档
   （`<repo>/.agents/doc-protocol.md`，或 `.zcode/` 版本，见上）。
2. 配套的 `references/`（实证等）一并并入覆盖档的第三节，或留在仓库内并加指针。
3. **删除项目级 skill 目录** —— 否则一旦通用层以同名安装到用户级，会把它遮蔽。
4. 更新仓库内引用它的地方（指令文件、日志头部）—— 指向新路径。
